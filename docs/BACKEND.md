# راه‌اندازی هسته سرور حضوربان

این commit یک هسته API و طرح پایگاه داده PostgreSQL اضافه می‌کند؛ هنوز پنل React به API وصل نشده و استقرار عمومی انجام نشده است.

## نیازمندی‌ها
Node.js 20 یا جدیدتر، Docker و Docker Compose، PostgreSQL 16.

## راه‌اندازی محلی
1. فایل `server/.env.example` را به `.env` در ریشه پروژه کپی کنید و مقادیر امن و واقعی وارد کنید.
2. رمز PostgreSQL را در محیط و فایل Compose تغییر دهید.
3. `docker compose up -d db`
4. `psql "$DATABASE_URL" -f server/schema.sql`
5. `npm install`
6. `npm run bootstrap` برای ساخت سازمان، شعبه و مدیر اولیه (فقط یک بار).
7. `npm run api` برای اجرای API.
8. `npm run dev` برای اجرای رابط فعلی.

## API فعلی
- `GET /api/health`
- `POST /api/auth/login`
- `GET /api/me`
- `GET /api/employees` و `POST /api/employees`
- `POST /api/attendance` و `GET /api/attendance`
- `GET /api/leave`، `POST /api/leave`، `PATCH /api/leave/:id/review`

تمام زمان‌های ثبت تردد از ساعت سرور PostgreSQL گرفته می‌شوند. رمزها با bcrypt هش می‌شوند، JWT هشت‌ساعته است، دسترسی نقش‌محور و گزارش ممیزی پایه وجود دارد.

## موارد لازم پیش از استفاده واقعی
- رابط کاربری هنوز از API استفاده نمی‌کند؛ داده‌های آن همچنان localStorage و حساب‌های نمایشی هستند.
- بارگذاری عکس به فضای ذخیره‌سازی خصوصی (مانند S3-compatible) و مسیر آپلود امضاشده نیاز دارد. API فعلاً فقط کلید شیء عکس را می‌پذیرد؛ فایل عکس را ذخیره یا تأیید نمی‌کند.
- ثبت/مدیریت دستگاه و صدور کلید دستگاه، بازیابی رمز، MFA مدیر، سیاست نگهداری عکس، پشتیبان‌گیری خودکار، مانیتورینگ، تست نفوذ و استقرار HTTPS هنوز باید تکمیل شوند.
- محاسبه شیفت، تأخیر، اضافه‌کاری، حقوق و دستمزد و تشخیص چهره پیاده‌سازی نشده‌اند.
- پیش از ذخیره عکس یا داده زیست‌سنجی کارکنان، اطلاع‌رسانی و مبنای قانونی، حداقل‌سازی داده، سطح دسترسی و زمان حذف باید تعیین شود. تشخیص چهره بدون رضایت/مبنای قانونی و آزمون liveness نباید فعال شود.

این هسته را قبل از بهره‌برداری عملیاتی باید تست، بازبینی امنیتی و به رابط کاربری متصل کرد.
